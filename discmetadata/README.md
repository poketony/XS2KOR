# 실행 파일 텍스트 번역

**이 폴더의 `SLPS_strings.txt`에서 두 번째 `|` 뒤의 원문을 번역하고
`2.Rebuild.bat`를 실행하면 기존 통합 패치까지 반영한 `slps_253.68.new`(Disc 1),
`SLPS_253.69.new`(Disc 2), `MainMenu.txd.new`가 한 번에 만들어집니다.**
OV02 항목도 수정했다면 `OV02.OVL.new`가 함께 만들어집니다. 기존 OV02 결과가 있으면 번역을 원복한 경우에도 최신 내용으로 갱신합니다.
게임에 넣을 때는 `.new`를 뺀 이름으로 사용하고, 함께 나온 파일은 함께 적용하세요.
ELF·OV02는 해당 디스크 루트, **MainMenu.txd는 아카이브 안의
`yosikawa/MainMenu.txd`**에 넣습니다. metadata 폴더는 결과 보관 위치일 뿐입니다.

TXT는 원본에서 추출했으며, 요청한 아이템 문구 4개는 번역해 두었습니다. UTF-8로 저장하세요.
Python 3.10 이상이 필요하며 별도 패키지는 필요 없습니다.

작업 폴더명은 `discmetadata`입니다. 두 디스크의 번역 TXT는 이 한 파일로 통합했습니다.
변환 전 양쪽 TXT·도구·BAT·설정은 `codex-lab/metadata-unify/backup`에 보존했습니다.
양쪽에서 번역된 항목은 모두 보존했고 서로 다른 번역의 충돌은 없었습니다.
원본 ELF·OV01·OV02는 두 디스크에서 바이트 단위로 같아 한 벌을 공유합니다.
OV01은 수정하지 않으므로 필요할 때 이 폴더의 기준 파일을 사용합니다.
`SYSTEM.CNF`는 디스크별 부팅 파일명이 다르므로 서로 바꾸지 마세요. 이 도구는 CNF를 출력하지 않습니다.
기존 `slps_253.68`은 과거 패치본이며 새 산출물이 아닙니다. 게임에는 `.new` 결과를 사용하세요.

## 편집 규칙

```text
005791C8|4/7|名前
```

위 줄은 다음처럼 마지막 부분만 바꾸면 됩니다. 주소와 `4/7`은 그대로 둡니다.

```text
005791C8|4/7|이름
```

- `4/7`은 원문 4바이트, 원래 위치의 수용량 7바이트라는 뜻입니다. 종단 NUL은 별도입니다. 자동 재배치 대상도 이 숫자는 고치지 않습니다.
- 한글은 기존 `yosikawa/XENOSAGA KOR-JPN.json` 대응표로 자동 변환됩니다. 보통 한 글자 2바이트이며, 대응표에 없는 글자는 오류로 중단합니다. 게임에는 해당 한글 폰트가 필요합니다.
- `{0B}`, `{1901}` 같은 제어코드는 내용과 순서를 유지하세요. `%d`, `%3d`, `&03`, `&04`도 유지합니다.
- `\n`은 실제 개행 바이트, `\\n`은 게임 전처리용 역슬래시+n입니다. **원문이 쓰던 표기를 유지하세요.** 한 항목은 TXT의 한 줄에 씁니다.
- `005651C0`, `00578D98`에는 개수 자리인 **반각 `00`을 정확히 하나** 남기세요. `을/를 00개`처럼 앞부분과 공백을 바꿔도 빌더가 숫자를 기록할 위치를 함께 수정합니다. `000`, 전각 `００`, 중복 `00`은 거부합니다.
- 캠페인 설명 `002C9348`에는 번호 자리인 **반각 `01`을 정확히 하나** 남기세요. `캠페인No.01`처럼 번역하면 인코딩한 바이트 위치에 맞춰 숫자 기록 명령어 두 곳을 자동 조정합니다. 전각 `０１`, 중복·누락, 다른 숫자에 붙은 `001` 등은 거부합니다. 기존 127바이트 한계와 제어코드·버튼 표기는 유지하세요.
- 공백·알파벳은 자동 전각 변환하지 않습니다. 번역하지 않은 줄은 바이트 그대로 보존합니다. 삭제한 줄도 원문으로 남습니다.
- 검증한 두 영상 안내 문구는 아래 규칙으로 길이 초과를 자동 처리합니다. 그 밖의 초과·제어코드 손상·저장 공간 부족은 전체 리빌드를 중단합니다. 자동 절삭은 하지 않습니다.

### 길이 초과 자동 처리

**`001945E0`(영상 스킵)와 `00194610`(PAUSE)은 문장만 번역하고 평소처럼 BAT를 실행하면 됩니다.**

1. 둘 중 한 줄이 초과하면 두 문구의 인접 공간 안에서 짧아진 문구의 여유를 활용합니다. 시작 주소는 8바이트 정렬을 유지하고 코드의 참조도 수정합니다.
2. 인접 공간에 들어가지 않으면 초과 문구만 검토한 ELF 정렬 여백으로 옮깁니다. 파일 크기나 로드 주소는 늘리지 않습니다.
3. 적합한 연속 공간이 없거나 참조가 검증되지 않은 항목이면 저장하지 않습니다.

현재 48바이트 스킵 안내와 34바이트 PAUSE 안내는 1번으로 처리됩니다. 로그의
`[MOVE/NEAR]`는 인접 공간, `[MOVE/POOL]`은 대체 영역으로 이동했다는 뜻입니다.
TXT의 주소는 원본 항목 ID이므로 이동 후에도 그대로 유지합니다. 삭제한 행의 문구도 원문으로 유지됩니다.

대체 영역은 80바이트 한 구간이며 종단 NUL·정렬도 이 공간을 사용합니다.
따라서 대체 영역 한 문장의 최대 길이는 79바이트입니다.
인접 공간을 쓸 때의 한계는 두 문구의 합산 길이에 따라 달라집니다.
**모든 204항목의 초과를 자동 처리하는 기능은 아닙니다.** 다른 문구와 OV02는
고정 길이 복사·문장 중간 참조·오버레이 교체 여부를 별도로 검증하기 전까지 기존 제한을 유지합니다.

### 아이템 문구

```text
005651C0|18/23|을/를 00개 손에 넣었다!
00578D98|6/10|을/를 00개
00579670|2/7|을/를{20}
00579678|2/7|개{20}
```

`{20}`은 반각 공백 한 바이트의 명시적 표기입니다. 현재 TXT에는 두 항목 끝에 실제 반각 공백이
하나씩 들어 있습니다. 편집기가 줄 끝 공백을 지운다면 위처럼 `{20}`으로 써도 같은 결과입니다.

`00578D98`은 필드 아이템 획득 시 `아이템명 + 개수 문구`를 공용 버퍼에 조합하는 경로입니다.
짧은 문구만 별도 화면에 표시한다는 뜻은 아닙니다. 두 바이트 앞의 검증된 패딩을 사용하고
참조 두 곳을 함께 고쳐 최대 10바이트를 허용합니다. 이 항목의 주소 표시는 기존 ID를 유지합니다.
주변 `Dummy`와 코드에서 참조하는 빈 문자열은 보존합니다.

`00579670`은 별도 획득 알림 조합 경로의 조사입니다. 받침 자동 판별 없이 `을/를` 그대로 표시합니다.
같은 조합 경로의 단위 `00579678`은 `개 `로 번역했습니다. 조사와 단위 끝에 반각 공백이
하나씩 필요합니다. 1개일 때는 숫자·단위를 생략하고 조사 뒤에 동사가 바로 붙습니다.
기존 `00569010`의 `手に入れた`는 아직 원문이므로 해당 알림 전체의 번역은 이 조각도
편집해야 합니다. 공백은 자동 삽입되지 않으며 동사 앞에 다시 넣으면 중복됩니다.

## 출력과 원본

- 원본: 이 폴더의 `slps_253.68.original`. 두 디스크 원본의 내용이 같으므로 이 한 파일을 공유합니다.
- OV02 기준: 이 폴더의 기존 `OV02.OVL`.
- 기존 이 폴더의 `slps_253.68`은 수정된 파일이므로 **리빌드 입력으로 사용하지 않습니다.**
- 입력 ELF·OV02·폰트 대응표의 SHA-256을 확인합니다. 다른 버전이면 중단합니다.
- 원본 파일과 기존 번역 TXT는 덮어쓰지 않습니다. **기존 `.new`는 검증 완료 후 자동 갱신**하므로 `2.Rebuild.bat`를 반복 실행하면 됩니다. 같은 결과면 `[UNCHANGED]`로 표시하고 다시 쓰지 않습니다.
- 각 출력은 `.pending`에 완전히 기록하고 내용을 확인한 뒤 `.new`로 교체합니다. 정상 완료 시 임시 파일은 남지 않습니다. 저장 실패 시에는 로그에 표시된 `.pending`을 확인하세요. 여러 출력 전체가 하나의 원자적 교체는 아니므로, 실패한 실행의 결과는 적용하지 말고 오류 해결 후 리빌드를 완료하세요.
- TXT를 아직 번역하지 않아도 실행 코드 패치가 있으므로 ELF와 메뉴 TXD를 출력합니다.
  저장 없이 검사만 하려면 이 폴더에서 `python -B elf_text_tool.py verify`를 실행하세요.
- TXT는 준비돼 있으므로 다시 추출하지 마세요. 기존 `1.Export.bat.lock`은 잠금 상태로 유지합니다. CLI `extract`도 기존 TXT를 덮어쓰지 않습니다.
- 기본 빌드는 양쪽 ELF 이름을 함께 출력합니다. 필요할 때만 CLI `--disc 1` 또는 `--disc 2`로 단일 이름을 지정할 수 있습니다. 어느 경우에도 같은 공통 TXT를 읽습니다.
- 원본 한 파일(약 5.6MiB)을 XS2KOR 안에 따로 보존하며 다른 작업 폴더를 참조하지 않습니다. 이 파일은 편집·교체하지 마세요.
- 완성한 `.new`를 사용자가 적용 폴더에 원래 이름으로 옮기는 단계만 수동으로 수행합니다. 적용 폴더의 ELF를 교체해도 이 도구의 원본에는 영향이 없습니다.

## 기존 통합 패치 포함

`think`에서 사용하는 공용 팝업의 ASCII 본문도 기존 큰 글자군으로 표시하도록 수정했습니다.
번역 TXT에 `!`, `?`, `,`, 영문·숫자를 반각으로 입력해도 해당 팝업에서는 기존 전각 입력에
대응하는 글리프로 표시하고, 전용 폭 계산도 전각 기준으로 맞춥니다. TXT 자체는 변환하지 않습니다.
공백도 이 팝업의 큰 글자 모드 폭을 따르므로 기존 줄 길이와 화면 넘침은 게임에서 확인하세요.
이 변경은 팝업 초기 설정과 전용 폭 계산에 한정합니다. cf·영상 자막·공용 루비 처리기·폰트 파일과
명시적 작은 UI 설정은 바꾸지 않습니다. 전투 아이템 목록 이름의 기본 경로는 원래 큰 글자 모드라
임의로 수정하지 않았고, 개수 열의 작은 숫자도 유지합니다. 목록 이름의 실제 이상 사례는 별도 재현이 필요합니다.
분석·검사·한계는 `codex-lab/context-font/README.md`를 참고하세요.

메모리카드 브라우저의 첫 줄만 `XenosagaEPII-번호`로 통일하는 패치도 자동 적용합니다.
XS3와 같은 전각 Shift-JIS 영문이며, 저장 번호·둘째 줄 지역명·인게임 이름·세이브 식별자는
바꾸지 않습니다. 첫 줄 길이에 맞춰 줄바꿈과 번호/둘째 줄 기록 위치만 조정합니다.
기존 메모리카드 파일은 수정하지 않으므로 새 실행 파일로 새 슬롯에 저장한 뒤 표시를 확인하세요.
이 변경을 위해 추가로 옮길 데이터 파일은 없으며 외부 작업 환경에 자동 복사하지 않습니다.

2026-10-04 최종 수정의 실행 코드 패치를 리빌드 때 자동 적용합니다.

- 버튼 아이콘 앞뒤에서 타이핑이 멈출 때 공백 폭 복구. 타이핑 속도·진행 위치는 유지합니다.
- think 계열 팝업은 큰 글자 모양을 유지하면서 반각 공백·문장부호의 이동 폭만 줄입니다.
  영문·숫자와 한글·전각 공백, 명시적 작은 글자·비례폭·루비 및 별도 전투 목록의 글자는 유지합니다.
  새 ELF 적용 후 게임을 재부팅하세요. 이전 세이브스테이트는 이전 실행 코드를 복원할 수 있습니다.
- 확인된 전투 이름·수량 목록은 이름칸 안의 반각 공백만 좁히고 수량 열과 패딩은 유지합니다.
  메인 메뉴 하단 설명문도 쉼표·반각 공백을 좁힙니다. 이미 좁은 일반 획득 대화와 CF는 그대로입니다.
  TXT·MainMenu TXD·폰트를 수정하는 기능은 아니며, 기존 스택/힙 예약 크기도 추가로 바꾸지 않습니다.
- 저장·불러오기 목록의 `데이터가 없습니다`도 해당 문자열의 반각 공백만 좁힙니다.
  데이터 유무 판단·실제 로드 처리·저장 데이터 이름/시간과 정렬 좌표는 바꾸지 않습니다.
- 특전 획득/느낌표와 EP1·프릭스 하단 보상 문구의 정렬.
- 특전 확인과 일반 저장·불러오기에서 `슬롯 1`/`슬롯 2`의 숫자 한 바이트 교체.
- `../0.xenosaga0/yosikawa/MainMenu.txd.txt`를 읽어 짝이 맞는 메뉴 TXD도 함께 생성합니다.
  슬롯 접두부, 정렬 기준 문구, 안내문 선행 공백, 폰트 폭, 12,288바이트 로드 영역을 검사합니다.
  이 조건이 달라졌다면 저장하지 않고 재검토를 요구합니다. TXT나 기존 TXD를 자동 수정하지 않습니다.

**기존 통합본에 맞는 메뉴 TXD를 이미 적용했다면 새 ELF만 교체해도 됩니다.**
현재 생성되는 메뉴 TXD는 그 이전 정상본과 같습니다. 이후 메뉴 TXT를 바꿨다면
함께 생성된 새 TXD를 적용하세요. 다른 곳에서 리빌드한 TXD와 임의로 섞지 마세요.

기존 통합 실행 코드 패치는 원본 대비 160바이트를 변경합니다. 여기에 아이템 문구 편집에 따라
숫자 기록 명령어 4곳과 짧은 문구 참조 2곳, 캠페인 번호 기록 명령어 2곳을 조정합니다. 문자열 슬롯과 겹치지 않으며,
원래 명령어와 패딩을 확인한 뒤 적용합니다. 이미 패치한 ELF를 입력으로 사용하지 않습니다.
원본 기반 TXT의 문구는 번역한 만큼만 적용하므로, 옛 ELF에만 있던 영상 일시정지 안내
번역 두 항목을 자동으로 되살리지는 않습니다. 한글 폰트 파일도 별도 게임 자산입니다.

## 포함 범위와 한계

디스크당 204항목: 메인 일본어 UI·조합 문구 34개, 사용 여부 추가 확인 문구 1개,
영문 UI 90개, 일본어 디버그·진단문 44개, OV02 일본어 안내 21개 및 영문 설치 상태 14개.
디버그와 영문 그룹은 선택 사항입니다. 파일 경로·스크립트 함수명·폰트 코드표·
숫자 데이터를 번역 문구로 섞지 않았습니다. 모든 ASCII 진단 로그를 나열한 목록은 아닙니다.
OV01에서는 일본어 번역 대상을 확인하지 못해 리빌드하지 않습니다.

일반 항목은 원래 문자열 위치와 최대 8바이트 정렬 슬롯 안의 연속된 0 패딩만 사용합니다.
짧은 아이템 문구는 위에서 설명한 두 바이트 앞쪽 재배치를 사용합니다.
영상 안내 두 문구는 필요할 때 위 자동 재배치와 주소 구성 명령어 수정을 사용합니다.
텍스트 편집 단계는 ELF 헤더와 파일 길이를 바꾸지 않습니다.
그 뒤 통합 패치가 지정한 명령어와 RX 세그먼트 크기를 변경하며 파일 길이는 유지합니다.
팝업 폭 도우미는 ELF 파일의 헤더 패딩에 보관하고 별도 로드 세그먼트로 BSS 뒤에 읽습니다.
커널 힙과 libc 할당 시작점을 함께 조정해 그 공간을 예약하며, 기존 힙 용량과 스택 위치·크기는
유지합니다. 기존 네 로드 세그먼트·엔트리·BSS 초기화·텍스트 재배치 풀은 변경하지 않습니다.
메모리카드 제목 패치는 `.sbss` 앞 정렬 여백 96바이트에 들어가며, 해당 로드 세그먼트의
파일 크기와 실행 권한 플래그도 갱신합니다. `.sbss`나 기존 텍스트 재배치 공간은 사용하지 않습니다.
무제한 장문 번역은 지원하지 않습니다.
줄 폭, 고정 좌표, 문자 출력 경로에 따른 한글 표시 여부는 게임 화면에서 확인해야 합니다.
텍스트만의 무수정 왕복은 원본과 바이트 단위로 일치합니다.
최종 출력은 통합 패치와 번역에 따른 숫자·참조 수정이 추가되므로 원본 전체 해시와는 다릅니다.

OV02 문자열은 메인 ELF에도 내장되어 있어 두 사본을 동기화합니다.
별도 OV02만 또는 메인 ELF만 고치면 실행 경로에 따라 원문이 다시 나올 수 있습니다.

Disc 1에는 `slps_253.68.new`, Disc 2에는 `SLPS_253.69.new`를 `.new`를 뺀 이름으로 적용합니다.
두 ELF의 내용은 같고 이름만 다릅니다. 메뉴 TXD와 변경된 OV02 결과도 양쪽에 동일하게 적용합니다.
외부 ROM 작업 폴더의 `disc1metadata`·`disc2metadata` 구분은 그대로이며 사용자가 결과를 직접 옮깁니다.
이 통합은 XS2KOR 내부 작업 폴더만 바꿨으며 ROM 빌더·외부 경로는 변경하지 않았습니다.

개발 검증: `python -B -m unittest discover -s codex-lab/ovl-analysis -p "test_*.py" -v`
(XS2KOR 루트에서 실행). 분석 근거는 `codex-lab/ovl-analysis/README.md`에 있습니다.
팝업 폭·다른 폰트 경로 CPU 검증: `python -B codex-lab/context-font/punctuation/validate.py --deployed`.
상세 구조와 한계는 `codex-lab/context-font/punctuation/README.md`에 있습니다.
전투 이름칸·메뉴 설명 후속 검증은 `python -B codex-lab/context-font/item-spacing/validate.py --deployed`.
범위와 미확인 보상 UI는 `codex-lab/context-font/item-spacing/README.md`를 참고하세요.

공통 확인창 본문에는 반각 공백 전용 보정이 포함됩니다. 문구 하나를 그리는 동안에만 적용하며,
캐릭터명·시간·숫자 칸·전각 공백·작은 글자/루비는 변경하지 않습니다.
